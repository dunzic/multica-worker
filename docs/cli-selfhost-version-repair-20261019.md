# 自部署 CLI 版本修复与验收

## 需求与边界

- 目标：工作区成员选择在线智能体进行创建时，不再因自部署 CLI 的版本格式错误被拦截；版本、安全和能力校验保持启用。
- 已确认原因：服务器提交 `14ec157507ba93f2f079c83b487f6de68909b924` 的 CLI 上报 `main-14ec15750`。Claude 运行时在线且该字段存在，但前后端不能解析。部署前只核对提交，没有校验版本。
- 用户授权：修复构建与替换前校验，重新构建并替换服务器 CLI，在无运行任务时重启守护进程并复测。
- 范围：Linux 服务器 CLI 与部署脚本；使用现有服务校验运行时注册和前后端版本判定。保持同一份服务器功能源码，不升级 Claude 等智能体工具。
- 初始修复授权不包括：数据库配置或业务数据变更、简历重跑、Git 提交/推送、新 Release、桌面或移动安装包、网站容器重启。服务器修复后，用户另行授权将本次代码提交、合并到 `main` 并推送到自有仓库；此授权不包含再次部署或发布安装包。
- 用户流程：打开创建入口 → 选择在线智能体 → 版本检查通过 → 可以继续输入创建要求。实际触发模型和生成任务不作为本次无业务写入验收；若未执行，明确标为未验证。

## 实施顺序

1. 留存当前 CLI、部署脚本、运行时身份、容器状态和非敏感配置摘要；确认源代码提交与自有远端主线一致。
2. 使用真实可达的稳定 Git 标签、提交距离和当前提交派生版本。自部署派生构建使用 `X.Y.Z+selfhost.N.g<commit>`，与公共 Release 区分；不伪造或移动标签。无标签、源码不干净、基线不匹配时失败，不退回 `main-*`。
3. 同一提交重新编译 CLI；校验完整构建提交、分发基线、必需能力、目标架构和内置 `version --check-compatibility`。不覆盖正在运行的后端镜像。
4. 将版本生成、构建后兼容性校验、替换前验证接入服务器现有部署脚本；保留 RDS 必需连接配置及隔离边界。
5. 再次确认运行与待回传队列为空，保留启动参数及进程环境，在可恢复备份就绪后原子替换并重启守护进程。失败则恢复原 CLI，并验证旧运行时恢复；不回滚数据库。
6. 读取真实注册元数据与心跳；检查所有原运行时 ID/工作区归属保留，Claude 恢复正确版本判定。复查网站就绪和其他容器未重启。
7. Review 最终脚本及差异，运行针对性测试，记录实际执行层级与未验证边界。

## 验收原则

- 本次不修改 UI；真实服务器运行时、版本注册和门槛校验是必需验收。单元测试不替代实际创建任务的业务验收。
- 如开展浏览器/桌面检查，先检测扩展屏、验证测试窗口实际位置，再操作和截图；无凭据或屏幕控制受限则明确记录，不冒用账号。
- 不打印口令、令牌、完整进程环境或简历内容；仅收集必要的非敏感版本、标识和状态证据。
- 发现活跃任务先暂停替换；发现安全、身份丢失或版本校验失败不得宣称通过。

## 源码入库与持续验证

- 入库范围为版本生成/候选校验器、旁置测试、本验收记录及对应 CI 接线。服务器环境相关的 `.deploy/`、一次性操作材料、备份、凭据和运行证据不进入 Git；现有服务器部署入口已经调用同一校验器。
- 后续构建在干净源码目录调用 `python3 scripts/selfhost-cli.py metadata --repo .`，将输出的 `version` 和完整 `commit` 作为构建参数。候选必须来自该源码，不能把线上旧二进制改写成新版本。
- 替换前调用 `python3 scripts/selfhost-cli.py check --repo . --binary /absolute/path/to/candidate --os linux --arch amd64`；校验退出非零时停止，不执行替换或重启。该命令只做校验，不负责部署、空闲保护或回滚。
- 提交前补齐 `script-checks` 对 Python 测试的调用，以及校验器和测试文件的 CI 路径过滤。用路径过滤/工作流测试证明这两类文件的后续修改会触发校验，再重跑针对性回归；远端 CI 结论以对应提交的实际运行结果为准。
- 入库前复核结果：新增的 3 项 CI 接线回归先复现失败，接入后 `scripts/ci-scope.test.mjs` 共 47 项通过；同时重跑版本/候选校验 14 项、操作保护合成测试 4 项、发布兼容性 22 项、前端版本判定 17 项，共 104 项通过，离线分发基线检查通过。上一轮服务器 Go 测试和实际运行时证据继续保留，本次 Git 发布不再次部署或触发真实智能体运行。

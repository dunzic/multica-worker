# 工作树草稿保留：修复与上线验收计划

## 目的、授权和范围

用户在本地资源上启动或继续智能体运行时，任务工作树必须包含当前未提交文件内容；已由智能体修改的内容也不能被旧草稿覆盖。原目录、暂存区、HEAD 和未提交状态属于用户，快照过程不能改动它们。

本轮基线为 `75d446bdcad83c1fff4cf66c80ede62f5ce1e9a7`。报告、统一聊天列表和桌面导航修复已推送；上线前的后端 CI 暴露既有草稿保留失败，本地 10 轮重复测试有 4 轮复现。用户已授权一并修复，回归和 CI 通过后再部署。

- 影响范围：Go 运行时的本地 Git 工作树快照与后续运行；不改变报告、聊天、数据库结构、权限或客户端 UI。
- 根因：复制索引改变其修改时间，破坏 Git 对同时间戳等长编辑的内容复核。固定时间戳用例在修复前连续 3 次失败；修复保留同一文件描述符上的原索引时间，复制或校验失败时丢弃私有副本并重建。
- 安全边界：使用临时合成仓库；不运行真实智能体，不接触用户业务仓库或生产简历，不恢复或覆盖业务库。保留私有索引，不能退回写用户索引或删除用户锁文件。
- 发布范围：仅自有仓库和已授权服务器；不发布安装包或标签。服务器运行版本仍为 `1a3704d48`，源码为 `75d446bdc`，后续部署必须分别核对。

## 完成门槛

1. 根因由稳定失败用例证实；最小修复不得牺牲用户索引隔离和错误安全性。
2. 逐项自审，修复发现的问题，完成定向压力回归和相关全套；环境跳过不算通过。
3. 自有仓库 main 与工作分支推送 SHA 一致，远端必需 CI 成功后才允许上线。
4. 重新构建目标版本镜像，先验证候选服务再切换；记录线上 SHA 与恢复方法。服务器上的 CLI 守护进程须确认无活动任务、备份原二进制后更新并验证提交号；不发布用户安装包，不把服务器更新等同全部客户端发布。

### 最终代码自审

- 保留私有索引与用户锁隔离；不改变用户 HEAD、暂存区或文件内容。
- 同一打开文件读取时间与字节，避免源索引被原子替换时取到不对应的时间戳。
- 检查写入、关闭和时间设置结果；若目标文件系统把时间向未来取整，放弃缓存并重建，不放行可疑索引。
- 自审补强项：复制失败可能留下可解析但时间不可信的副本，必须删除后重建；损坏索引的重试也先删除私有副本。已修复，并由 W03 回归覆盖。

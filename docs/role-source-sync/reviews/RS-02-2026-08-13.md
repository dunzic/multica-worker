# RS-02 strategy and initial design review

Feature: Bounded scan and contract validation

Gate: strategy and initial design

Date: 2026-08-13

Decision: CONDITIONAL — adapter implementation may continue; no source registration or rollout

## Customer problem and measurable outcome

An administrator needs a complete, understandable preview of a role source before it changes the workspace. A successful scan must discover every supported source object, produce the same normalized digest for the same semantic content, identify blockers, and prove that neither workspace state nor source files nor secrets were mutated or exposed.

## Decision

Run AgentWaker filesystem scans only inside the selected daemon. Apply the daemon's existing top-level local-directory policy, then use a root-confined read-only filesystem for every descendant access. Normalize source contracts into the generic role-source manifest. Store artifact references and keyed secret-change digests, never artifact bodies or plaintext environment/MCP credentials, in the snapshot plane.

The first adapter supports AgentWaker schema 2.1 plus capability, binding and automation schema 1.0. Unsupported adapter capabilities remain false and cannot be advertised by the API/UI.

## Architecture expert review

Score: 2/3

Accepted evidence:

- adapter is isolated under server/internal/rolesource/agentwaker and implements the generic registry contract;
- clean absolute root and daemon policy validation are mandatory;
- os.Root confinement plus component-by-component Lstat rejects traversal, absolute paths, symlinks, non-regular files and common replacement races;
- strict JSON/YAML parsing rejects unknown configuration and contract fields;
- roles, skills, capabilities, bindings, environment declarations, MCP servers and automations use stable source identities;
- public artifacts become SHA-256 references; sensitive files influence only HMAC-keyed evidence;
- environment values are converted to per-key HMAC digests and best-effort cleared after scan;
- the source tree digest covers every contract/artifact read without publishing sensitive bodies.

Open objections:

- supporting text files beneath skill directories are bounded and represented; binary assets and undeclared capability files still require the content-store policy;
- capability adapter/environment/MCP requirements are normalized, but runtime availability resolution is not yet connected;
- cron, timezone and supported issue-title variables are validated; scheduler parity must remain covered as upstream rules evolve;
- content-addressed artifact upload/fetch and scan consistency retry are not implemented;
- daemon heartbeat protocol and server-side immutable snapshot persistence are absent.

## Product expert review

Score: 1/3

Accepted evidence:

- the normalized preview can describe detected roles, dependencies, configured/missing keys and unresolved MCP references without values;
- unsupported watch, secret-transfer and binary-artifact modes remain disabled;
- failed scan leaves the last-known-good runtime state untouched by construction.

Open objections:

- no source settings page, scan progress, preview or diagnostics UI exists;
- diagnostics have technical codes but no localized recovery guidance;
- skipped/supporting file disclosure and source completeness indicators are incomplete;
- administrators cannot yet approve, reject or compare a snapshot.

## Test expert review

Score: 2/3

Accepted evidence:

- tests prove scan is read-only by comparing source-tree entries before and after;
- snapshot JSON is checked for absence of exact .env body and secret values;
- changing a secret changes manifest and tree digests while keeping plaintext absent;
- registry traversal and final/intermediate symlinks are rejected;
- unknown config fields and undeclared MCP environment references are covered;
- generic manifest tests enforce stable IDs, artifact paths/digests, keyed environment digests, dependency references and deterministic hashing;
- ordinary and race-enabled package tests pass.
- bounded fuzz sessions cover environment parsing, path confinement and canonical JSON idempotence.
- the adapter successfully scanned the two-role/two-capability code2rich absorption fixture after aligning the source automation kind with its actual contract.

Open objections:

- YAML structure and full-manifest fuzzing still need persistent CI coverage beyond the bounded local fuzz sessions;
- no file-change-during-scan stress test, size/count aggregate tests or network-filesystem test;
- no real 12-role AgentWaker corpus golden test;
- no daemon disconnect, duplicate report, stale scanner version or server persistence tests.

## CEO review

Score: 2/3

Accepted evidence:

- the adapter absorbs the valuable code2rich contracts without importing its plaintext-secret and hard-coded-control-plane risks;
- a normalized, secret-free catalog is a reusable basis for enterprise role supply chains and future source ecosystems;
- preview-first design lowers the commercial risk of bulk role upgrades.

Open objections:

- there is no usable customer workflow or measured scan cost yet;
- no second adapter proves ecosystem leverage;
- the 10,000-user capacity profile, support model and staged rollout economics remain untested.

## Security, privacy and data-loss blockers

- secret transfer and encrypted storage are intentionally not implemented and remain disabled;
- source configuration and snapshots are not persisted yet, so tenant authorization and retention are unproven;
- supporting scripts and binary assets require explicit review and content-store policy before they can be considered complete;
- no real source may be registered until daemon protocol authentication and server snapshot redaction tests pass.

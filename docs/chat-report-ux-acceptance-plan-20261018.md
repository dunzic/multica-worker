# 聊天列表与报告协作体验需求及验收计划

本轮解决两个用户流程问题：单聊和群聊应在同一个聊天列表中查找、切换；阅读报告时应能查看原文件、下载原件并填写可保存的协作反馈。组件保持通用，不为简历筛选单独设计交互。

状态：本地实现、代码差异评审和自动化回归已完成；真实 Chrome 的 7 条综合流程通过，macOS 原生客户端已执行关键操作。逐项证据和未完成边界见[验收执行记录](chat-report-ux-verification-20261018.md)，不能据此宣称全平台、全场景验收通过。代码基线为 `1a3704d480f73f50f0dc66e6c6c9b5144616bff4`，本轮为其上的未提交差异。

授权边界保持不变：仅本地开发、代码评审、回归和真机截图验收；不提交、推送、部署、打包或重跑真实简历。仅修正已授权的本地测试环境，原数据库、账号和生产人工反馈不变。

## 功能定位和需求边界

### 统一聊天列表

聊天是找到并继续一段对话的统一入口。单聊和群聊是会话类型，不应要求用户先进入两个不同页面再找人或群。

- **C1 统一入口**：左侧一个列表混合显示当前工作区中有权查看的单聊和群聊，右侧展示所选会话；不是把不同会话的消息混在一起。
- **C2 可识别和可查找**：群名称、群标识与单聊对象清晰可辨；保留单聊置顶和归档能力，其他会话按真实最近活动排序。名称、摘要和时间不得互相遮挡。需要群消息摘要时补充服务端受权限约束的摘要，不逐群拉取全部消息。
- **C3 连续操作**：创建单聊或群聊后仍在同一聊天布局；切换、返回、刷新和旧链接定位不丢会话与话题，不串用草稿或待发送附件。
- **C4 群内话题**：话题属于群内部的第二层导航；只有一个默认话题时不把“未命名”当成第二个群名。多话题明确显示当前选择，并保留已有话题和消息 ID。
- **C5 兼容和隔离**：网页、桌面共享列表和会话主体；既有群组深链接继续可用。列表合并不合并底层所有权，不改变群成员权限或已有消息状态。

本轮不新增搜索、群置顶、群归档或新的群未读统计模型。保留已有单聊未读语义；群组目前没有对齐的摘要和未读返回字段，不得拿本地时间猜未读数量或显示虚假“已读”。这些扩展不能作为混合列表已经完成的附带承诺。

### 报告展示与协作反馈

报告不仅要能阅读，还应支持“读一条结果 → 查看原件 → 填写反馈 → 保存 → 同事继续跟进 → 回看修改记录”。报告是展示内容，反馈是由平台保存的结构化数据；两者应在同一预览工作区里容易找到，而不是要求用户理解存储结构。

- **R1 原件操作**：报告中的“预览原件”打开真正的原件预览，不触发下载；“下载原件”走认证下载，得到正确文件。完成后能回到报告原位置，未保存反馈不能丢失。
- **R2 可发现的协作入口**：工具栏提供始终可见的“报告反馈”文字入口和明确的展开状态，不仅是无说明的图标。有已配置反馈的报告首次打开时展示反馈区，普通无配置附件不强迫用户配置。
- **R3 可操作的反馈记录**：可以识别报告条目与反馈记录的对应关系，找到该条记录的编辑操作、可选值、当前值和保存状态；行数较多时不要求凭附件 UUID 匹配。宽屏并排，窄屏可切换或纵向阅读，不能把正文和表格挤成逐字竖排。
- **R4 真实保存和多人接续**：显示正在保存、成功或失败；保存成功后刷新、重开及第二位有权限成员均读到同一结果。冲突保留用户输入并给出明确处理路径，修改记录显示修改人、时间和前后值。
- **R5 通用字段**：继续支持每份报告最多 20 个可配置字段及现有类型。用质量检查和交付跟进数据验收通用性，简历字段只是另一个实例，不硬编码到公共组件。
- **R6 不覆盖和不越权**：现有报告、行 ID、人工值与修改记录原样保留；原文件单独鉴权。HTML 保持不透明来源沙箱，不取得令牌、Cookie、存储访问或任意弹窗权限。

用户已确认“标记丢失”指看不到可操作选项和入口，而非已保存值消失。本次只读核查的指定 HTML 报告有 17 条初始记录、4 个字段、18 条初始化历史，人工值均为空；不应自动填充为“待约”、通过或其他人工决定。

### 已确认的问题及开发约束

| 问题 | 当前证据 | 开发约束 |
| --- | --- | --- |
| 单聊和群聊分成两套页面 | `chat-page.tsx` 只向列表提供单聊；`chat-groups-page.tsx` 另建群列表 | 使用共享会话外壳，保留两类数据与权限边界，避免复制一套聊天实现 |
| HTML 中原件链接无响应 | 指定报告 34 个原件链接均带 `target="_blank"`；预览 iframe 只有 `allow-scripts`，禁止弹窗 | 主界面受控接管站内附件动作；不直接增加 `allow-popups`、`allow-same-origin` 或顶层导航权限 |
| 反馈控件难以找到 | `feedbackOpen` 默认 `false`，工具栏只显示表格图标 | 明确文字入口；依据授权读取到的反馈配置决定初始展示；保留用户主动收起的选择 |

原件动作桥接必须把报告中的内容视为不可信输入：校验当前 iframe、动作类型、附件标识、允许的来源和当前用户激活；父页面重新鉴权，使用现有预览/下载通路。任意 URL、伪造消息、后台脚本或旧 iframe 消息不能借此执行操作。不能把凭据或文件内容回传给报告脚本。外部链接不自动当成站内附件操作。

## 验收环境与测试数据

- 已使用受管理环境 `chat-report-ux-20261018`：专用数据库 `multica_chat_report_ux_20261018_992`，网页 `13992`、API `19072`、桌面开发服务 `6166`。未复制账号密码，未改原数据库或生产连接；连接配置不入 Git。
- 使用两名有权限的测试成员 A、B，一名工作区内但非群成员 C，以及被撤权成员 D。准备另一个工作区，用于验证切换和隔离。
- 准备单聊、两个群组、单话题和多话题群、空会话及已有草稿。只使用虚构人员及合成消息。
- 准备一份通用质量报告与一份交付跟进报告，每份含至少 17 条可关联原件的记录；另备超过 50 条记录、20 个字段的边界报告。配置文本、数字、日期、是／否、单选、多选，含空值、已有值和已有历史。
- 原件覆盖 PDF、TXT 和已支持的 Office 预览；使用带 `_blank` 的绝对预览链接、相对下载链接、带空格和中文名称的文件。用自包含测试 HTML 复现现有报告结构，不拷贝真实简历或候选人资料。
- 真机主环境为本机 macOS 实际浏览器；桌面端另启动本次代码的实际 Electron 客户端，使用隔离配置。记录版本、窗口尺寸及构建来源。仅跑浏览器不能完成桌面验收。
- Windows 原生客户端是独立验收项；没有可用 Windows 主机时标为阻断，不能以 macOS 或浏览器设备模拟通过代替。原生移动端不在本轮开发范围，窄窗口测试仅代表响应式网页。
